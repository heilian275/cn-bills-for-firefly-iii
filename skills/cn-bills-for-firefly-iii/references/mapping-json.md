# mapping JSON

分类判断在 SKILL.md 里，这里只约定产物格式。预览和导入脚本都读这个文件。数组，每笔一条，单条长这样：

```json
{
  "序号": 1,
  "来源": "支付宝",
  "日期": "2026-01-02", "时间": "12:34",
  "对方": "示例小吃店", "商品": "外卖订单",
  "金额": "25.00", "收支": "支出",
  "账单分类": "餐饮美食",
  "type": "withdrawal",
  "源": "某银行储蓄卡(1234)",
  "目标": "餐饮食品",
  "细分": "日常餐饮",
  "置信": "高",
  "操作": "导入",
  "ext": "alipay:2026010223001164EXAMPLE01",
  "描述": "外卖订单"
}
```

字段含义：

- `type`：`withdrawal` / `deposit` / `transfer`；`操作`：`导入` / `跳过`。跳过的行，其余映射字段可以填占位值。
- `源` / `目标`：用户 Firefly III 里的真实账户名。两端的账户类型由 `type` 决定，见 `references/firefly-iii.md` 的「交易模型」。照勘察输出的账户清单填，不要自己造账户。
- `细分`：category 名。用户的结构里不用 category 就留空。
- `用户tag`：只有用 tag 体系时填，和「细分」二选一。导入时并进交易的 tags。
- `币种`：可选。填勘察输出里这个实例人民币的实际 code。不同版本默认值不同，别猜。留空就不发送，靠账户币种继承，前提是账户币种是人民币。
- `备注`：可选。写进交易的 notes，也显示在预览里。「理由」是同义别名。
- `ext`：external_id，格式见 `references/bill-formats.md` 的「external_id」。
- `描述`：写进 Firefly III 的 description。风格照用户实例里既有交易来。
- `置信`：高 / 中 / 低，由 agent 自评。高：用户历史里有先例，或者账单机制明确；中：比较明确，但用户的口径可能个性化；低：最佳猜测。预览页优先展示中低置信和跳过项。不要为了省事把判断都标成「待定」，那等于把判断推回给用户。
